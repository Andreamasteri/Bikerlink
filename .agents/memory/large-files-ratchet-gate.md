# 450-line ratchet gate

`scripts/check-large-files-ratchet.ts` (+ `scripts/lib/large-files-core.ts`) enforces a per-file
TS/TSX line limit. It runs inside `scripts/post-merge.sh` after every task merge.

**Current limit: 450 righe** (abbassato da 600 su richiesta utente — quando un file viene splittato,
i nuovi file devono stare sotto 450, non 600, così c'è margine prima del prossimo split).

**Line counting:** `content.split("\n").length` — this is `wc -l` + 1 for files that end in a
trailing newline. The `.large-files-baseline` numbers were generated by the same counter, so compare
against split-length, NOT `wc -l`. To drop a LEGACY file "under baseline N", its split-length must be
`<= N` (the gate fails only on `lines > baseline`).

**Rule classes:**
- NEW file > 450 and not in baseline → blocked. Split it (preferred) or get a user-authorized marker.
- LEGACY file (in `.large-files-baseline`) → blocked only if it GROWS above its stored count.
- LOCKED marker file → drift > +5 over declared limit blocked; raising the declared limit is blocked.
- `--update-baseline` is HUMAN-ONLY (needs `BIKERLINK_HUMAN_BASELINE_UPDATE=1`). Agents must not use it
  EXCEPT when the user explicitly requests a global threshold change — in that case the baseline update
  is authorized by the policy change itself.

**Why this matters:** the gate runs post-merge on `main`. If a merged task lands an offending file,
the post-merge script exits 1 and **every following merge keeps failing on the same files** until they
are fixed directly on main — the failure is sticky and not specific to the new task. Resolve by
splitting/trimming the offending files on main (a pure mechanical extraction verified by typecheck is
enough), not by touching the failing task.

**How to apply:** when a post-merge failure cites the "Ratchet 450 righe" gate, read the named files,
split new oversized components into sibling files (move their styles too), and for a LEGACY +1
regression just remove one line to return to baseline. Re-run `npx tsx scripts/check-large-files-ratchet.ts`
and both typechecks before finishing.

**i18n files (`lib/i18n/en.ts`, `lib/i18n/it.ts`) recur here:** every feature that adds translation
keys grows them past baseline, and the keys CANNOT be deleted (merged features use them). Non-destructive
fix: pack several flat dotted keys onto a single physical line (`"a": "x", "b": "y", ...`) in the same
logical group — line count drops while every key/value is preserved. Keep en/it symmetric. Full-project
`tsc --noEmit` often times out (>120s); since compaction changes no keys/values the typecheck state is
unchanged, so an `esbuild --bundle` syntax check on the two files is sufficient to confirm validity.
