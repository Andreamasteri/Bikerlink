# Sweep 404 runtime — Task #2632

Data: 2026-05-27
Backend live: http://localhost:5000 (healthy, status:ok)

## Metodo

1. Estrazione di tutti i path letterali `/api/...` dal codice client (`app/`, `components/`, `hooks/`, `lib/`)
2. Estrazione di coppie `(METHOD, path)` da `apiRequest("METHOD", "...")` (tagged-template ` `…` ` inclusi)
3. Per ogni `(METHOD, path)` esplicito: curl con metodo estratto. Per path letterali senza method esplicito: curl GET (default fetcher TanStack).
4. Sostituzione di `:param` e `${var}` con `1` per testare path dinamici.
5. Classificazione: 200/304/400/401/403/409/422 = OK; 404 = bug candidato; 5xx = errore server (segnalato, non in scope sweep 404).

## Note sul rate di falsi positivi

Il metodo di sweep curl-based ha falsi positivi quando:
1. `new URL(path, base).toString()` è preludio a fetch con metodo diverso da GET (upload POST).
2. queryKey base TanStack vs URL completo con `${id}` sono entrambi presenti (estrattore prende quello senza interpolazione).
3. Sostituire `${id}` con `1` può fallire l'autorizzazione prima di toccare il route handler.

Per una sweep più accurata occorre sessione autenticata + ID reali (scope #2619 — UI/E2E).
