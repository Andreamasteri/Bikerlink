What & Why
Le build EAS in managed workflow eseguono expo prebuild --clean che rigenera completamente la cartella android/, cancellando qualsiasi file depositato lì manualmente — incluso adi-registration.properties necessario per la verifica pacchetto su Google Play Console.

La soluzione corretta è un config plugin Expo (withDangerousMod) che scrive il file direttamente durante il prebuild, così sopravvive alla rigenerazione. Il profilo production in eas.json è già configurato per buildare AAB (buildType: "app-bundle").

Snippet account Google Play: CKO4ROI4RUDE2AAAAAAAAAAAAA

Done looks like
Esiste un config plugin (es. plugins/withAdiRegistration.js) che scrive android/app/src/main/assets/adi-registration.properties con contenuto CKO4ROI4RUDE2AAAAAAAAAAAAA durante il prebuild
Il plugin è registrato nell'array plugins di app.json
Il file android/app/src/main/assets/adi-registration.properties è presente e corretto dopo l'esecuzione di npx expo prebuild localmente
Un build AAB è stato avviato su EAS con profilo production (Android only)
L'utente riceve il link diretto su expo.dev per scaricare l'AAB
Out of scope
Pubblicazione effettiva su Play Store
Modifiche alla logica di business o all'UI
Build iOS
Steps
Crea config plugin — Crea plugins/withAdiRegistration.js usando withDangerousMod per scrivere il file adi-registration.properties con contenuto esatto CKO4ROI4RUDE2AAAAAAAAAAAAA nella directory android/app/src/main/assets/ durante la fase prebuild. Creare la directory se non esiste.

Registra plugin in app.json — Aggiungi "./plugins/withAdiRegistration" nell'array plugins di app.json.

Verifica locale prebuild — Esegui npx expo prebuild --platform android --clean e verifica che android/app/src/main/assets/adi-registration.properties contenga esattamente CKO4ROI4RUDE2AAAAAAAAAAAAA.

Avvia build AAB su EAS — Lancia il build con profilo production per piattaforma Android e comunica all'utente il link su expo.dev per scaricare l'AAB risultante.
